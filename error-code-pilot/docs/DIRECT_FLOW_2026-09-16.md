# 减少重复确认与维修反馈点击 — 2026-09-16

根据用户对两张截图的直接反馈，优化010之后的双语交互。知识、受控症状、机型范围、维修动作、验收要求及PIE权限边界未改变。

## 原因与改动

第一处原本不是再次确认“刀盘有异响”，而是确认尚未收集的适用条件：实际割草异常与仅功能测试异常可能使用不同路径，1202也不能绕入通用割草换件。原来的“确认具体情况／是否一致”表达重复，回答后还需一次Continue。

现在普通已明确选择直接进入指导；需要补充信息时，直接问具体场景。例如“割草问题在什么情况下出现？”，选项明确实际运行、测试及1202条件。选完直接进入指导或PIE处理，没有第二次Continue。原选择始终可见；返回后未修改信息，不重复追问。只有两条既有割草路径使用这类场景问题，未来限定条件变化会显示完整原条件，不会沿用简写而漏掉新限制。

第二处复选框原本要求代理自报已完成检查，但系统没有读取设备或验收证据，勾选并不能证明测试真的通过。现在移除复选框，将“勾选＋已解决”合并为 **已验证，问题已解决**（英文 **Checks passed — issue resolved**）。保留“仍未解决”和“维修后再次出现”；完整验证要求仍在按钮之前显示。点击只形成此次使用中的代理反馈，不自动验证、关单或写入生产系统。

| 操作 | 原来 | 现在 |
|---|---|---|
| 补充实际故障场景后查看指导 | 点“是”再点“继续” | 选择具体场景后直接进入 |
| 选择明确候选或具体分支后 | 再点“继续” | 直接进入对应结果 |
| 反馈验证通过且已修复 | 勾选复选框，再点“已解决” | 点击一个含义明确的反馈按钮 |

模糊错误码搜索仍只给候选；它不能自动选择维修路径。选错场景、不确定、1202冻结、错误码与现象不匹配时，仍保持适当的PIE处理。修改机型、现象、错误码或固件后，旧结果继续失效。
